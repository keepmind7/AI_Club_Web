# Club Manager QA 방법

## 원칙

- 코드를 고치지 않는다. 찾은 문제를 근거와 함께 보고한다. 고치는 일은 담당 에이전트가 한다.
- 파일이 있는지가 아니라 **연결 지점이 맞는지**를 본다. 백엔드와 프론트엔드가 각자는 맞아도 서로 다른 모양을 주고받는 결함이 가장 흔하다.
- 실제로 실행한 명령과 출력만 근거로 쓴다. 실행하지 못한 검사는 "실행 못 함"과 이유를 적는다.

## 검사 순서

### 1. 실행 검사

```bash
cd backend && .venv/Scripts/python manage.py check && .venv/Scripts/python manage.py test club
cd frontend && npm run build
```
`.venv`나 `node_modules`가 없으면 각 스킬의 설치 명령으로 먼저 설치한다.

### 2. 실제 API 호출 (백엔드를 띄워서)

임시 DB(`DB_PATH`를 `_workspace/qa.sqlite3`로)에 마이그레이션하고, `manage.py shell`로 운영진 1명·회원 2명·정원 1명짜리 유료 모임을 만든 뒤 `runserver`를 띄워 `curl`로 호출한다 (쿠키 파일과 `X-CSRFToken` 사용).
- 로그인 → me → 모임 목록 → 신청(회원 A 확정, 회원 B 대기) → A 취소 → B 승격 확인
- 회원으로 `/api/dashboard` → 403
- 응답 JSON의 필드 이름·형식을 계약 예시와 한 필드씩 비교한다.
검사가 끝나면 서버를 끄고 임시 DB를 지운다.

### 3. 경계 대조 (코드 읽기)

| 대조 | 방법 |
| --- | --- |
| 계약 ↔ 백엔드 | 계약의 엔드포인트 표를 `config/urls.py`와 하나씩 맞춘다. 각 응답 dict의 키를 계약 예시와 비교한다 |
| 계약 ↔ `types.ts` | 타입 필드 이름·null 가능 여부·열거값을 계약과 비교한다 |
| `api.ts` 호출 ↔ 백엔드 URL | 프론트의 모든 호출 경로·메서드가 백엔드에 있는지, 백엔드 엔드포인트 중 호출되지 않는 것이 있는지 |
| 라우터 ↔ 링크 | `router.ts` 경로와 모든 `to=`, `router.push(`, `href=` 값 |
| CSRF·세션 | 프론트가 POST에 `X-CSRFToken`을 붙이는지, 백엔드 `me`가 쿠키를 심는지, Vite 프록시와 Caddyfile 경로가 `/api`, `/club-admin`, `/static`을 모두 넘기는지 |
| 신청 상태 전이 | confirmed/waitlisted/cancelled 전이가 계약대로만 일어나는지 (`status` 대입 지점을 모두 찾는다) |
| 배포 | compose의 서비스 이름(`django`)과 Caddyfile의 프록시 대상, DB 볼륨 경로와 `DB_PATH`, `.env.example`과 settings가 읽는 변수 |

### 4. 요구사항 대조

`동작 흐름.md`의 흐름 11개와 계획서 6장의 화면 목록을 하나씩 확인해 구현 위치(파일:줄)를 적는다. 빠진 것은 필수 수정이다.

### 5. 보안

- 회원이 다른 회원의 납부·출석 데이터를 볼 수 있는 경로가 없는지
- 휴면·탈퇴 회원이 기존 세션으로 API를 쓸 수 없는지
- `DEBUG=False`일 때 보안 쿠키 설정, `SECRET_KEY`가 코드에 하드코딩되지 않았는지
- 로그인 실패 제한 동작

### 6. 불필요한 코드 (ponytail)

`ponytail:ponytail-review` 스킬을 불러와 기준으로 삼는다. 쓰이지 않는 함수·파일, 요청하지 않은 기능, 한 번만 쓰이는 추상화, 계약에 없는 엔드포인트, 추가 의존성을 찾는다. 이 항목은 동작에 문제가 없으면 `권장`으로 분류한다.

## 보고 형식

```markdown
# QA 보고서

## 실행 결과
- 백엔드 테스트: N개 통과 / M개 실패 (출력 요약)
- 프론트 빌드: 성공/실패
- API 호출 시나리오: 결과

## 필수 수정
| # | 영역(backend/frontend) | 파일:줄 | 문제 | 근거 | 수정 방향 |

## 권장
| # | 영역 | 파일:줄 | 내용 |

## 요구사항 충족표
| 흐름/화면 | 구현 위치 | 상태 |

## 실행 못 한 검사
```

필수 수정 = 계약 위반, 요구사항 누락, 테스트·빌드 실패, 보안 문제, 실제 동작 오류.
